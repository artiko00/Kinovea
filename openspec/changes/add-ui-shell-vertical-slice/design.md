# Design

## Context

See proposal.md for motivation. Constraints shaping this design:

- Everything the shell needs from the domain already exists after changes 01 to 08: preferences model (`kinovea-core`), KVA metadata with drawings and keyframes (`kinovea-metadata`), `Renderer` trait (`kinovea-render`), video reader with frame cache (`kinovea-video`, FFmpeg backend). The shell adds no domain logic.
- The original shell is split across `Kinovea/Kernel.cs` (menus and supervisor, 55 KB), `Kinovea.Services/Window/*` (descriptors, `WindowManager`), `Kinovea.FileBrowser/` (explorer and thumbnails), `Kinovea.ScreenManager/ScreenManager.cs` (154 KB: screen list, dual layout, every screen-level menu). The menu structure and hotkey table are the user-visible contract; the WinForms layout is not.
- Linux only, no display in CI. UI tests must run headless.
- The end goal includes an MCP server that never opens a window: the `kinovea` binary must keep a path that does not initialise a GPU context.

## Goals / Non-Goals

**Goals:**
- A thin egui shell whose logic lives in view-model structs testable without egui.
- One vertical slice proving open → draw → save on Linux with a KVA the original app accepts.
- Menu and hotkey parity from day one, with disabled entries where the feature lands in a later change.

**Non-Goals:**
- Reproducing WinForms pixel layout or porting any `Designer.cs`.
- Full player screen controls and the 29-drawing toolbar (change 15).
- Theming beyond egui defaults.

## Decisions

### D1. Toolkit: `egui` through `eframe` with the `wgpu` backend
Decided with the user during exploration. Alternatives: `iced` (Elm-style, canvas less direct), `slint` (declarative, custom canvas harder). egui's immediate mode fits a tool whose core is a custom-painted canvas over a video frame, and `egui::Painter` maps naturally onto the `Renderer` trait. New dependencies, **approval required**: `eframe`, `egui`, `egui_extras` (image loading for thumbnails), `wgpu` (via eframe feature), `rfd` (native file dialogs), `egui_kittest` (dev-dependency). Versions pinned in `rust/Cargo.toml` `[workspace.dependencies]`.

### D2. New crate `kinovea-ui`; `kinovea` stays the thin binary
`rust/kinovea-ui` holds the app (`App`, panels, dialogs, view-models). `rust/kinovea/src/main.rs` parses arguments (`--version`, `--headless` reserved for change 13, file paths) and calls `kinovea_ui::run(args)`. Alternative: put the UI in the binary crate; rejected because integration tests and the MCP server need the UI logic as a library. **Approval required** (new crate).

### D3. View-model first, egui second
Every panel is a pair: `ShellState`/`FileBrowserState`/`ScreenManagerState`/`WorkspaceState` structs holding state and pure methods (`open_file`, `set_screen_count`, `swap`, `handle_hotkey`), and an egui `show(&mut self, ui)` function that only reads state and emits `UiEvent`s. Tests target the state structs with plain `cargo test`; `egui_kittest` tests target `show` for a few interaction flows. This mirrors the original split between `ScreenManager` (logic) and `ScreenManagerUserInterface` (WinForms) without the event spaghetti.

### D4. Menu and command tables as data
Menus are a static table (`menus.rs`) of `MenuEntry { id, label_key, hotkey, enabled_when }`; hotkeys a `CommandTable` keyed by `CommandId` with the original default bindings from `HotkeySettingsManager.cs`, stored in preferences (`Keyboard` tab wires later). This keeps parity verifiable by a test that compares the table with a fixture extracted from the C# defaults (`tests/cases/ui/hotkeys.json`, generated once by hand from the C# source, not by the oracle).

### D5. Descriptor compatibility via `kinovea-core` XML types
`WindowDescriptor`, `ScreenDescriptorPlayback`, `WorkspaceDescriptor` are implemented in `kinovea-core::window` with `quick-xml` (already a dependency after change 05) and tested against descriptor files captured from the Windows host (`tests/fixtures/window/*.xml`, generated by a new `WindowArea` in `Kinovea.FixtureGen` that writes one descriptor of each kind through the original `WriteXML`). Unknown elements are kept as raw XML to round-trip.

### D6. Headless UI tests in CI
`egui_kittest` with its software renderer runs widget tests and snapshot tests without a GPU. Snapshot PNGs live under `rust/kinovea-ui/tests/snapshots/` with a per-pixel tolerance. `rust.yml` needs `libxkbcommon`, `libwayland`/X11 dev packages for `eframe` to link; **approval required** for the workflow edit. The vertical-slice integration test uses a 2-second synthetic clip generated with `ffmpeg -f lavfi testsrc` in a build step (pattern from change 08).

### D7. Strings
All user-visible text goes through `kinovea_ui::strings::S` (English constants keyed like the original `.resx` keys, e.g. `mnuOpenVideo`). No `.resx` is touched; change 18 replaces the module by Fluent lookups. The config rule "add an English .resx string task" is therefore satisfied by the strings module.

## Legacy superseded

Removed in `remove-dotnet-solution` once this change is archived:
- `Kinovea/Kernel.cs`, `Kinovea/Program.cs`, `Kinovea/NativeMethods.cs`, `Kinovea/UserInterface/*` (`KinoveaMainWindow`, `FormPreferences2`, `PreferencePanels/*`, `FormWindowManager`, `FormWindowProperties`, `FormWorkspaceManager`, `FormWorkspaceName`, `FormAbout`, `SplashScreen`, `SupervisorUserInterface`).
- `Kinovea.FileBrowser/*` (whole project).
- `Kinovea.Services/Window/*` (`WindowManager`, descriptors), `Kinovea.Services/Commands/*` (hotkeys), `Kinovea.Services/WinForms/*`.
- `Kinovea.ScreenManager/ScreenManager.cs`, `ScreenManagerUserInterface.cs`, `Thumbnails/*`, `UserInterface/*` (color picker, sliders, toaster), `AbstractScreen.cs`, `LoaderVideo.cs`, `SummaryLoader.cs`.

## Risks / Trade-offs

- [eframe fails to link or start in CI without a display] → `egui_kittest` CPU path for tests; the real `eframe` startup is only exercised by a smoke test marked `#[ignore]` that developers run locally.
- [Thumbnail generation blocks the UI] → thumbnails decode on a worker thread pool with a bounded queue and an LRU cache keyed by path and mtime; the grid shows placeholders until ready.
- [Descriptor XML drift from the original] → fixture round-trip tests from D5; unknown elements preserved.
- [egui's immediate mode makes modal dialogs awkward] → a single `DialogStack` in `ShellState`; one modal at a time, matching the original behaviour.
- [Menu parity test rots when the original changes] → the table fixture is versioned and reviewed, not regenerated automatically.

## Migration Plan

1. Land `kinovea-ui` with the empty window, menus and hotkey table (no video).
2. Add descriptors and the navigation pane; restore layout between launches.
3. Add the minimal player screen and the save path; run the vertical-slice test and the manual check on the Windows host.
Rollback: delete `rust/kinovea-ui` and restore `rust/kinovea/src/main.rs`; no other crate depends on the UI.

## Open Questions

- Whether Wayland or X11 is the primary session for packaging (change 19); eframe supports both, the test harness does not care.
- Default thumbnail size and columns; pick the original medium size and adjust after first use.
