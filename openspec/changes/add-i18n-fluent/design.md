# Design

## Context

See proposal.md for motivation. Current state:

- Five `Languages/` folders hold `<Component>Lang.resx` (English) and `<Component>Lang.<lang>.resx` for 41 other languages (42 files each). Totals: Root 203, ScreenManager 565 (French 561, Tamil 4), FileBrowser 31, Camera 33, Updater 10. 18 ScreenManager strings use positional placeholders.
- Code accesses strings through generated classes (`ScreenManagerLang.Key`, 568 distinct keys referenced). `LanguageManager` lists 41 languages with native names and a low-coverage list; `Kernel.cs` switches `CurrentUICulture` at run time and rebuilds menus. The menu is Options > Language.
- Weblate (see `localization.md`) pushes `.resx` PRs; Weblate also supports Fluent (`.ftl`) components.
- The Rust UI crates (`kinovea-ui`, capture module) currently hold English literals.

## Goals / Non-Goals

**Goals:**
- Zero translation loss: every translated string that has an English counterpart survives conversion.
- One macro call per UI string, with compile-time checked identifiers in tests.
- Weblate keeps working on the new files with no manual step beyond pointing the component at the new path.

**Non-Goals:**
- Pluralization rules beyond what the original strings express (they use no plural categories).
- Converting `Tools/helptools` documentation.

## Decisions

### D1. Fluent over gettext or a custom JSON (requires approval: new crate and dependencies)
Fluent (`fluent-bundle`, `fluent-langneg`, `unic-langid`) handles named variables, language negotiation and fallback chains, and Weblate supports it. gettext would need a C library or `gettext-rs` and keyed-by-English-text semantics that break when English wording changes; the original uses stable keys, which Fluent identifiers preserve.

### D2. Identifier scheme
`<component>-<key>` lowercased with underscores to hyphens: `ScreenManagerLang.mnuAngle` → `screenmanager-mnuangle`. Keeping the original key makes the mapping mechanical and lets the converter be re-run. One file per language, `locales/<lang>/kinovea.ftl`; locale codes follow the original (`zh-CHS` → `zh-Hans`, `zh-CHT` → `zh-Hant`, others unchanged).

### D3. Converter as a Rust binary in `tools/i18n`
`tools/i18n/resx2ftl` is a small crate added to the workspace (`rust/Cargo.toml` member `../tools/i18n/resx2ftl`), using `quick-xml`. It converts `{0}`→`{ $arg0 }` and escapes Fluent special characters. Run from `make i18n` and in CI: `resx2ftl --check` exits non-zero when committed `.ftl` differ from a fresh conversion, until `remove-dotnet-solution` deletes the `.resx` and the check step with them.

### D4. Runtime API
```rust
pub struct Localizer { bundles: Vec<FluentBundle<FluentResource>> } // selected locale then English
pub fn tr(id: &str) -> Cow<'static, str>; macro_rules! tr { ($id:literal) => ...; ($id:literal, $($k:ident = $v:expr),+) => ... }
```
Locale files are embedded with `include_dir` so the AppImage has no external files; a `KINOVEA_LOCALES_DIR` override allows translators to test without rebuilding. Language change swaps the `Localizer` behind an `Arc<RwLock>` and triggers an egui repaint; egui has no cached text so no rebuild is needed.

### D5. Language list and low coverage
`locales/languages.toml` generated by the converter from `LanguageManager.cs` (code, native name, low_coverage flag). The Options > Language menu reads it; low-coverage entries show the same marking as the original.

### D6. Tests as the completeness gate
`kinovea-i18n/src/lint_test.rs`: parse every `.ftl`, compare identifiers and variable sets against English, fail on orphans and variable mismatch, print missing counts. `tests/references_test.rs`: scan `rust/**/*.rs` for `tr!("...")` literals and assert each exists in English. Both run in `make verify`.

## Legacy superseded

`*/Languages/*.resx` and `*Lang.Designer.cs` (read-only until `remove-dotnet-solution`), `Kinovea.Services/Language/LanguageManager.cs`, the `CurrentUICulture` switching in `Kinovea/Kernel.cs` (`RefreshUICulture` chain through every `IKernel`), `Kinovea.targets` `MoveLanguages` target. The AGENTS.md rule "edit only the English `.resx`" becomes "edit only `locales/en/kinovea.ftl`". New UI text in Rust is added to the English `.ftl`, never to `.resx`.

## Risks / Trade-offs

- [Translators' in-flight `.resx` PRs on Weblate after conversion] → freeze: lock Weblate, merge pending PRs, run the converter, switch the component; documented in the hand-off task.
- [Fluent syntax characters in translations (`{`, `}`, `*`, `[`)] → converter escapes them and the lint test parses every file, so a bad escape fails CI, not the user.
- [egui font coverage for CJK, Arabic, Tamil, Thai] → bundle Noto fonts subsets per script in `kinovea-ui` (decision recorded in change 14; this change adds the test that each locale renders without tofu glyphs for its sample string).

## Migration Plan

1. Converter and committed `.ftl` files. 2. Crate and macro, replace literals in `kinovea-ui` and capture module. 3. Language menu. 4. Weblate switch (human action, documented). Rollback: delete `locales/` and revert the macro replacements; `.resx` untouched.

## Open Questions

- Whether Weblate should keep one component per original project or one component for the whole `kinovea.ftl`; the file layout supports both. Decide with the Weblate admin at hand-off.
