# Design

## Context

See proposal.md for motivation. Constraints:

- The numeric work is done: `kinovea-measurement` (change 04: `CalibrationHelper`, `CalibratorPlane`, `CameraPoser`, `UnitHelper`, lens `DistortionHelper`/`CameraCalibrator`), `kinovea-kinematics` (change 03: `TimeSeriesCollection`, `FilteredTrajectory`, Butterworth, linear/angular kinematics), `kinovea-tracking` (change 10: template matching, circle tracker, `TrackabilityManager`, `DrawingTrack`). This change is view-models and widgets only.
- The original forms: `FormCalibrateLine` (140 lines), `FormCalibratePlane` (344), `FormCalibrationValidation` (576), `FormCalibrateDistortion` (325), `formConfigureTrajectoryDisplay` (345), `ControlDrawingTrackingSetup` (634), and five OxyPlot forms (`FormPointsAnalysis`, `FormAngularAnalysis`, `FormAngleAngleAnalysis`, `FormMultiTrajectoryAnalysis`, `FormTrackAnalysis`, ~2 000 lines) sharing `PlotHelper` (export) and `TimeSeriesPlotData/Specification`.
- OxyPlot has no Rust port. `egui_plot` provides line series, points, annotations, legends, zoom/pan and tooltips; it does not render to PNG headlessly by itself.
- Change 12 owns the CSV writer (`kinovea-export::csv`) and the oracle fixture `export.csv` per kinematics case.

## Goals / Non-Goals

**Goals:**
- Every dialog is a view-model with pure validation and apply logic, tested without egui.
- Plots show exactly the series the library computes; no numeric code in the UI.
- Graph PNG export is deterministic and headless (CI snapshot).

**Non-Goals:**
- OxyPlot visual parity; axis styling follows egui defaults.
- New kinematic components or units.

## Decisions

### D1. `egui_plot` for interactive charts, headless renderer for PNG export
`egui_plot` (new dependency, **approval required**) draws the interactive windows. `Save graph…` and `Copy graph` do not screenshot egui; they re-render the same `PlotSpec` (series, axes, labels, size) through a small `plot_raster.rs` that uses `kinovea-render`'s `tiny-skia` backend. Alternatives: `plotters` for both (no interactivity), screenshot of the egui texture (needs GPU, non-deterministic in CI). Two renderers for one spec keeps PNG output testable by snapshot.

### D2. One `AnalysisWindow` model, five configurations
`analysis/model.rs`: `AnalysisKind { LinearKinematics, AngularKinematics, AngleAngle, Scatter, Track }`, `AnalysisModel { series: Vec<SeriesEntry{ id, label, enabled, color }>, component, time_model, plot: PlotSpec }` with `rebuild(&Metadata, &CalibrationHelper)` producing `PlotSpec` from `kinovea-kinematics`. This mirrors the shared `TimeSeriesPlotData`/`TimeSeriesPlotSpecification` the original forms already had and removes the five-way copy of export code (`PlotHelper`) that `dupelens` would flag.

### D3. Dialog view-models return a `Result<Apply, Reject>`
`measurement/calibrate_line.rs`, `calibrate_plane.rs`, `coordinate_system.rs`, `calibration_validation.rs`, `lens_distortion.rs`, `time_calibration.rs`, `tracking/parameters.rs`, `tracking/trajectory_display.rs`: each holds editable fields, `validate() -> Result<(), String>` (e.g. convexity), `apply(&mut Metadata) -> HistoryMemento` so `OK` is undoable through `HistoryStack` (change 05), `Cancel` drops the memento. egui `show` only edits fields and calls these.

### D4. Live previews reuse player painting
The plane and lens dialogs need a preview over the current frame. They receive an `Arc<Frame>` and paint with the `EguiRenderer` of change 15 using `kinovea-render` drawing primitives (`DrawingPlane`, `DrawingDistortionGrid`), so the preview equals what the player shows after `OK`.

### D5. Measurement labels and `Display measure` live in metadata, not UI
The submenu reads `Drawing::supported_measures()` and writes `Drawing::measure_label_type` (change 05 KVA element `MeasureLabelType`); the UI only lists what the drawing declares, so new drawings get the menu for free.

### D6. Clipboard
`arboard` for text and image clipboard (**approval required**; shared with change 15's `Copy image`/`Copy time`). Alternative: egui's built-in text clipboard only (no images). Headless tests use a `Clipboard` trait with an in-memory fake.

### D7. CSV through `kinovea-export`
`Copy data`/`Save data…` build a `Table` and call `kinovea_export::csv::write`, so the bytes equal the oracle `export.csv` fixture (generated by `KinematicsArea` through the original `CSVHelper`, extended in task 1.1).

## Legacy superseded

Removed in `remove-dotnet-solution`:

- `Kinovea.ScreenManager/Measurement/LensDistortion/FormCalibrateDistortion.cs`.
- `Kinovea.ScreenManager/PlayerScreen/Forms/FormCalibrateLine.cs`, `FormCalibratePlane.cs`, `FormCalibrationValidation.cs`, `FormConfigureTrajectoryDisplay.cs`.
- `Kinovea.ScreenManager/PlayerScreen/Controls/SidePanelControls/ControlDrawingTrackingSetup.cs` (its binding moves to `tracking/parameters.rs`).
- NuGet `OxyPlot` and `OxyPlot.WindowsForms` references (removed from `packages.config` in `remove-dotnet-solution`).

## Risks / Trade-offs

- [`egui_plot` lacks a feature the original uses (colour-gradient line for angle-angle time)] → draw the diagram as segments with per-segment colour (`PlotItem::Line` per pair) behind a feature flag; acceptable at the sample counts involved (< 10 k points).
- [PNG export differs from on-screen plot] → both come from one `PlotSpec`; the snapshot test guards the raster path, and `egui_kittest` asserts the on-screen series count and labels.
- [Dialog field layout of 9 lens parameters becomes long] → group physical and distortion parameters in two collapsible sections; `linelens` enforces the module split.
- [Tracking preview rectangle needs the viewport transform] → the dialog receives the `ImageTransform` from the player state (change 15) by reference.

## Migration Plan

1. Extend the oracle with `export.csv` per kinematics case and `calibration` dialog fixtures (plane sizes → world coordinates).
2. Land dialogs one by one, each behind its context-menu entry (enabled as it lands; menu entries exist disabled since change 14).
3. Land `AnalysisModel`, the five windows, PNG export.
Rollback: menu entries revert to disabled; no data format changes.

## Open Questions

- Default decimal precision for CSV from preferences versus the fixed precision the original `CSVHelper` uses; resolve by reading the fixture header produced in step 1.
