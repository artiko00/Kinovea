# Design

## Context

See proposal.md. Observed in the C# source:

- `CameraTracker` (1k LOC): `FindFeatures` (ORB or SIFT via OpenCvSharp, optional gray mask), `MatchFeatures` (`BFMatcher` Hamming/L1 with cross-check, ratio test, normalized distance threshold), `FindHomographies` (`Cv2.FindHomography` RANSAC with `RansacReprojThreshold`, inlier masks), `BundleAdjustment` (rotation-only model through `OpenCvSharp.Detail`), `BuildTracks` (chain inliers, `MinTrackLength`), `GetFeatures/GetMatches/GetTracks` for display, `ParseColmap`.
- `CameraTransformer`: `Initialize(tracker)`, `Transform(sourceT, targetT, p)` chaining `consecTransforms` forward or inverses backward; `WriteXml` attribute `type="Homographies"`, `Frame` elements with `timestamp`, `index`, matrix text.
- `VideoFilterLensCalibration`: samples frames, `FindChessboardCorners` on gray, `CalibrateCamera` (rational model, 30 iterations), `ProjectPoints` for reprojection error, results into `DistortionParameters`. `CameraCalibrator` is a thin wrapper used by import.
- `VideoFilterKinogram` (1.4k LOC): `GetBaseIndices`, `ClampOffset`, `GetDestinationRectangle`, `Interpolate`, `PadTiles`, `UpdateCache`, `Paint`, `DrawTile`, `DrawBorder`, `DrawLabels`; `KinogramParameters` serialization; export through `IDrawingHostView`.
- OpenCV is also used by `Metadata.cs` only to convert bitmaps to `Mat` for the trackers (not needed in Rust).

## Goals / Non-Goals

**Goals:**
- Everything that is not an OpenCV algorithm (parameters, serialization, transform chaining, tracks, kinogram) is pure Rust and always built and tested.
- OpenCV-backed algorithms sit behind one feature flag and one small adapter module so they can be swapped for pure Rust later.

**Non-Goals:**
- Bundle adjustment rotation model in this change: the original flags it experimental; serialization only supports homographies. Recorded as a later option.
- Pixel parity of the kinogram labels (fonts differ).

## Decisions

### D1. Feature `opencv` on `kinovea-measurement` (requires approval)
Crate `opencv` (rust bindings, needs `libopencv-dev` and `clang` at build time). Alternatives: pure Rust (`akaze` crate exists, no SIFT, no robust chessboard detector) or shelling out to Python; rejected now. The feature gates `src/camera_motion/cv.rs` (detect, match, find homography) and `src/lens/cv.rs` (chessboard, calibrate, project). Without the feature the estimator returns `Error::FeatureDisabled` from those steps while transformers, tracks, serialization and the kinogram stay available. CI runs both configurations.

### D2. Trait boundary for the vision backend
`trait MotionBackend { detect(&Gray, mask) -> Vec<Feature>; match(&[Feature], &[Feature], norm) -> Vec<Match>; homography(src, dst, threshold) -> (Homography, Vec<bool>) }` and `trait CalibrationBackend { find_corners(&Gray, pattern) -> Option<Vec<Point>>; calibrate(obj, img, size, iters) -> (Intrinsics, Vec<f64>, rms); project(...) }`. The OpenCV adapter implements both; tests of the pure logic use a `FakeBackend` returning scripted matches, so the estimator state machine is unit-tested without OpenCV.

### D3. Homography application is pure
`kinovea-geometry` (change 02) provides 3x3 matrices and projective mapping; `CameraTransformer::transform` chains them forward (`H_i ... H_j-1`) or with inverses backward, exactly as the original loops over `consecTransforms`. Inverses are computed once per transform at initialization.

### D4. Kinogram lives in `kinovea-render`
Layout and selection are pure functions in `kinovea-render::kinogram::layout` (ported `GetBaseIndices`, `ClampOffset`, `GetDestinationRectangle`, `Interpolate`, `PadTiles`); composition draws crops through the `Renderer` trait of `add-headless-renderer` (bilinear scaling of a crop into a cell, rectangles, text). This introduces a dependency of this change on `06 add-headless-renderer` in addition to 04 and 10; recorded in `openspec/roadmap.md` when archived.

### D5. Oracle areas
- `cameramotion`: FixtureGen renders a textured image by formula (deterministic pseudo-random blobs from the case seed), warps it by known per-frame translations/perspective with `Graphics.DrawImage` under a `Matrix`? No: GDI+ interpolation would differ from Rust; the frames are generated by inverse-mapping each pixel through the known homography with nearest-neighbour sampling, written into locked bits. Runs `CameraTracker.RunAll`, writes `homographies.csv` (frame, 9 values), `truth.csv`, `matches.csv` counts.
- `lenscalib`: renders chessboards by formula (board pose, intrinsics, k1 from the case; per-pixel inverse mapping through the distortion model) for N frames, runs `VideoFilterLensCalibration` logic through `CameraCalibrator` plus a direct `FindChessboardCorners` call, writes `intrinsics.json`, `corners.csv`.
- `kinogram`: renders frames whose pixels encode the frame index and a gradient, instantiates `VideoFilterKinogram(metadata)` with a `Cache` as frames container, sets parameters from the case (labels none, borders on/off), writes `kinogram.png` and `layout.json` (cell rectangles, selected indices, crop positions). The PNG is the only binary fixture of the roadmap; it is small (output 600x400) and `tests/fixtures/**` is already `-text`.

### D6. Tolerances
Camera motion: 0.5 px on truth, 2 px corner mapping versus original. Lens: 1 percent focal/center, 0.02 distortion. Kinogram: 2 per channel outside border/label masks, exact layout JSON.

## Risks / Trade-offs

- [`opencv` crate build time and `clang` requirement slow CI] → the feature job is separate and cached; the default job stays OpenCV-free.
- [SIFT availability differs across OpenCV builds] → ORB is the test default; SIFT cases are skipped with a message when the build lacks it (OpenCV ≥ 4.4 includes SIFT in main; Ubuntu 24.04 ships 4.6).
- [Nearest-neighbour synthetic warps produce aliasing that hurts feature matching] → textured images use large smooth blobs; tolerances are on medians.
- [Kinogram PNG fixture introduces a binary into git] → one small file per case, two cases; documented in `tests/README.md`.

## Migration Plan

Additive. The `kinovea` binary gains `--camera-motion <video>` and `--kinogram <video> <out.png>` subcommands for manual checks (feature-gated where needed). Rollback: remove modules and the feature.

## Open Questions

- Pure-Rust replacement for ORB and RANSAC homography (`akaze` + in-crate RANSAC): deferred; does not change the specs because the backend is behind a trait.
